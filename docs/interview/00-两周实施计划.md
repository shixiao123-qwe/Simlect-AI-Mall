## 需求契约设计

字段建议：categoryQuery、minPrice/maxPrice、scenario、hardConstraints、softPreferences；金额为非负 Decimal，区间上限不得小于下限。模型不能生成可信 categoryId、productId、库存或价格。分类词由真实分类映射确认；无法匹配时保留待澄清状态。

不把“低延迟”自动变成某个未提供的毫秒值；“全新”必须能在 Java 属性中找到证据，否则不能视为已满足。缺失品牌、库存或商品参数不能让模型补全。

多轮更新要区分未提供、不变、显式清除。更换品类时重新检索，不能沿用上一品类候选。需求合并后重新 Pydantic 校验；候选召回只生成 ID 列表，Java 再检查 SKU 上架、预算和库存，推荐排序只能在合格集合中进行。

## 评测口径

- 结构化准确率：按预先标注字段计算 exact match，并报告字段级错误；离线模型 mock 通过率不叫真实 LLM 准确率。
- 硬约束满足率：有返回商品中，逐个 SKU 用权威夹具或 Java 实际结果核对；零返回单独计覆盖率，不把空结果记成 100% 成功。
- MCP 成功率：区分传输成功、业务成功、预期错误被正确处理。
- 平均及 P95：保留每次测量和样本数；离线 mock 耗时不能代表线上推理时延。
- 故障分类：解析、校验、候选为空、库存不可用、Java 超时、MCP 超时、模型失败、鉴权拒绝。
- 基线：同一批数据、同一模式比较旧 search_products 与新流程；没有改造前真实数据时明确无可比基线。
