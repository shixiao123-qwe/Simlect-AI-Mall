## 1. 商品分页与分类缓存

原商品默认、价格、销量排序均缺少唯一键；同价、同销量、同创建时间的数据使用 offset 分页可能重复或遗漏。ProductController 的各排序及推荐列表现在均以 product_id asc 收尾。这个修复保证固定数据集与既定排序下的确定性，不承诺高频并发增删时 offset 分页仍是快照；更大规模可再评估游标分页。

新增 includeRecommended 可选参数，首页与启动预加载显式传 true。旧客户端无分类时默认排除推荐、空分类旧行为保留。没有为填满首页复制商品或伪造销量。

分类缓存仅用于无筛选、无分页、无显式排序的完整快照。命中后不查询分类表；筛选请求走 Mapper，不被全量缓存覆盖；树形/属性转换使用副本，避免修改缓存对象。属性统一批量读取后递归挂载，避免逐层重复查询。公开分类接口显式要求树与属性，保持前端形态。通用写入成功后刷新快照，修复删除子列表为空时的逻辑条件。

## 2. 工具结果协议与失败分类

原调用中部分错误靠中文前缀识别，传输完成就被统计为成功。新协议保留 SIMLECT_TOOL_RESULT 前缀和原卡片字段，使用 wireVersion=2，增加：

| 字段 | 含义 |
| --- | --- |
| status | success / empty / error / invalid_args / denied / transport_error / legacy |
| errorCode | 机器可读原因，如 NO_CANDIDATES、JAVA_TIMEOUT、MCP_TIMEOUT |
| retryable | 可供上层提示的只读重试信息；不触发自动重试 |
| degraded | 某条召回路径降级；返回商品仍须 Java 核验 |
| degradationCodes | 同一回合的多个降级原因 |
| legacy | 原工具或旧信封的兼容标记，不冒充新协议成功 |

无候选、无满足硬约束商品、ES 故障、Java 超时/拒绝/响应异常、MCP 超时/isError 分开表示。错误或空状态解析后丢弃卡片与商品事实 ID，避免旧数据复用。解析非法信封返回安全错误，不把原始内容交给模型。向量关闭不记为故障。

Retriever 新增请求局部诊断，保留旧列表返回类型和 fallback；区分 ES 失败后 fallback 成功与所有路径失败。现有 Prometheus 工具 Counter 改为按最终业务结果分类，不把 legacy 或 transport_error 计作 success。没有添加写操作自动重试，也没有替换原确认令牌、申请幂等和结果恢复机制。

旧业务工具内部仍有文本结果，因此通过 legacy 保留兼容；本轮未把每一个历史工具全部迁移成精确业务状态。前端文本与卡片继续兼容，无需一次性重写聊天界面。推荐、对比正文移除了 SKU hash 与 Java 实现词，结构化 verified.skuHash 继续用于安全核验。

涉及 Agent app/services/tool_invoke_result.py、mcp_streamable_client.py、mcp_tool_router.py、shopping_service.py，app/rag/retriever.py、app/mcp_server/server.py；新增 tests/test_tool_result_contract.py。相关旧评测夹具补足库存、当前 SKU 和真实申请响应字段，不放宽生产校验。

## 3. HTTP 生命周期与关联 ID

JavaInternalClient 原每次创建关闭 AsyncClient。现在应用 lifespan 内每事件循环复用一个有界客户端：总连接上限 12、keep-alive 6、空闲期限 20 秒；应用退出、启动失败、异常与取消路径均关闭资源。独立 CLI 或 asyncio.run 未进入 lifespan 时仍按请求关闭，避免跨 loop 遗留连接。

请求分别带自身 headers 和 timeout，不把用户认证存入共享默认 headers；Cookie 拒收且不回放，不自动跟随重定向，不自动重试 POST。FastAPI 使用 AsyncExitStack，MCP 的池绑定整个 ASGI 应用 lifespan，不绑定单个 MCP session。

新增 ContextVar 请求作用域及纯 ASGI 中间件，接受受限 UUID/32 位十六进制 ID，替换非法输入；通过 X-Trace-Id 连接 Python → MCP → Java，复用 Java 现有 TraceIdFilter 和 FeignTraceInterceptor。Java 内部调用日志只记阶段、关联 ID、耗时和安全错误类别，不记录认证、响应体或完整异常文本。

涉及 app/services/internal_http.py、request_context.py、java_internal_client.py、app/main.py；MCP client/server 配合传递。新增 tests/test_internal_http_lifecycle.py。

MCP 协议会话本轮仍按调用建立，未将可变 session 全局共享。连接复用是已实现的资源管理改进；没有改造前同条件性能基线，不宣称响应时间提升百分比，也没有加入 Grafana 等额外常驻服务。
