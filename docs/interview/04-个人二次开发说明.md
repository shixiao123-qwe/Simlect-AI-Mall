## 已完成：接通普通商品搜索

### 为什么修改

前端 `Simlect-front/Simlect-web/src/api/modules.ts` 原来提交 `/product/search`。ProductController.search 只抛“请使用搜索服务接口”异常，而 SearchController 没有商品检索方法。Search 服务已经有 EsSearchComponent.searchProducts，无需重写 Elasticsearch 查询。

### 修改文件

1. `Simlect-backend/Simlect-search/src/main/java/com/simlect/controller/SearchController.java`：新增 POST `/search/products`，校验关键词、价格区间、页码、排序，再复用 EsSearchComponent。
2. `Simlect-front/Simlect-web/src/api/modules.ts`：商品搜索改为 `/search/products`。
3. `Simlect-backend/Simlect-gateway/src/main/resources/application.yml`：新路径匿名访问；在 product 通用路由之前添加旧 `/api/product/search` 的精确兼容路由，SetPath 到 `/search/products`，目标为 Search。
4. `Simlect-backend/Simlect-search/src/test/java/com/simlect/controller/SearchControllerTest.java`：验证参数传递、无效预算/页码/排序在 ES 调用前拒绝。

### 前后调用链

原链路：Vue → Gateway product → ProductController.search → BusinessException。

新链路：Vue → `/api/search/products` → Gateway search → SearchController.searchProducts → EsSearchComponent.searchProducts → ElasticsearchOperations.search → PaginationResultVO → ResponseVO → Vue。

旧客户端：`/api/product/search` → 优先匹配 product-search-legacy → SetPath `/search/products` → 同一 SearchController。直接访问 Product 服务的旧方法仍明确拒绝；兼容发生在统一网关入口。

### 参数和失败处理

- 关键词不能为空、全空白或超过 200 字符；传给组件前 trim。
- 预算不得为负，最小价格不得大于最大价格。
- 允许排序字段 composite/price/sale，方向 asc/desc。未知字段不能直接透传到 ES。
- 页码 1～666；当前固定每页15条，避免越过 ES 默认 10000 结果窗口。
- 复用统一业务异常和 ResponseVO；ES 异常仍由已有组件转为“搜索服务暂时不可用”。

### 面试如何解释

问：你做了什么，而不是原作者做了什么？

答：原项目已有 ES 索引、分词和查询组件。我修复的是前后端与微服务边界的调用断点，增加输入校验，并让网关兼容旧客户端。没有把原有搜索算法算成自己的新增成果。

问：为什么在网关兼容旧路径？

答：搜索应由 Search 域承担。精确旧路由先于 product 通配路由匹配，直接转发到 Search，避免在 Product 再增加一层不必要 RPC。新客户端走清晰的新路径。

问：搜索价格符合预算，是否代表所有 SKU 都符合？

答：不是。现有 ES 使用商品 minPrice/maxPrice 区间相交语义，只用于候选检索。后续 AI 精确筛选必须查 Java SKU 权威价格和实时库存，返回具体匹配 SKU，不能把商品最低价当作所有规格价格。
