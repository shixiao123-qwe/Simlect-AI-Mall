# 本地模拟付款与售后成功路径

> 2026-11-02后续更新：售后已新增管理员审核、退货物流/人工验货、受控退款执行及实时进度。原文中“尚未实现审核履约”等是此前阶段记录，最新源码与验收见 [15-售后审核履约设计与验收](15-售后审核履约设计与验收.md)。

2026-11-02。在支付占位模式上增加显式用户点击的模拟付款，补齐网页售后成功路径的前提。没有升级依赖、直接改数据库状态或调用真实资金渠道。

## 新旧区别

以前 PayChannel4AliPay 的 localMockEnabled 只返回无HTML的支付单，queryOrder返回null；所以能下单但无法成为已付款。本次增加独立模拟确认接口，让Java用已有支付成功处理更新订单与支付记录。不把“创建支付单”误当成付款成功。

## Java执行链路与约束

用户点击按钮 -> Gateway `/api/order/localDemo/confirmPayment` -> `LocalDemoPaymentController.confirm`（登录态、@Valid）-> `LocalDemoPaymentService.confirm` -> 与原流程同一 Redis 支付生命周期锁 -> 读取支付单下全部子订单并检查同一归属 -> 读取真实金额 -> `OrderInfoService.paySuccess(PayOrderNotifyDTO)` -> 原状态条件更新、物流MQ、券逻辑及 `PayFeignSupport.markSuccess` -> 重读订单状态确认成功。

服务端要求三个条件同时成立：SIMLECT_PAY_LOCAL_MOCK_ENABLED=true、SIMLECT_PAY_DEMO_CONFIRM_ENABLED=true、SIMLECT_PRODUCTION_READY=false。确认开关默认false；若生产模式或未启用占位却开模拟确认，启动校验失败。接口调用时再次校验，不依赖前端隐藏。

客户端只传payOrderId，不接受金额、用户ID、状态或渠道流水。检查所有子订单都属于登录用户，拒绝真实支付已发起标记、关闭/取消/退款及未知状态，检查订单创建时间不超过现有order.expire.minute。超时消息未到也不能模拟支付。关闭订单不复活。

模拟渠道号为 `LOCAL_DEMO_` + payOrderId，可识别演示记录。重复调用仅在服务器已是本地模拟支付状态时返回alreadyPaid=true，不重复调用支付成功业务；非模拟已付款订单拒绝。原paySuccess拿同一Redisson可重入锁，不引入一套与关单无关的新锁。

## 前端

复用 usePaymentPage；开发环境收到占位支付单才显示按钮。点击时禁用重复操作，调用后再读取服务器订单，不能单靠前端session标记宣称成功。成功页明确“模拟付款成功（未扣款）”；刷新时使用服务器channelOrderId识别模拟记录。原正常支付宝HTML路径不变，本地演示不展示支付宝担保说明。

## 验证结果与边界

Java 166项通过，其中新增服务17项、Controller3项，其余为原订单108项、超时关单19项和售后19项。前端11项函数行为检查通过、电脑/移动支付页SFC编译通过。覆盖关闭、过期、其他用户、真实支付已发起、错误金额/未知状态、重复确认、生产限制和服务器回读失败。

Java测试模拟Redis及业务依赖，没有调用真实支付。复用了已有支付成功流程，但不能据此声称模拟付款网页全链路或并发压力测试已完成。本地Order已重建并启动健康，其他服务保持运行。vue-tsc类型检查通过。通过真实前端代理验证：未登录返回901；演示账号调用不存在订单返回“订单不存在或无权访问”，证明新路由、登录和开关已生效，未改变任何订单。用户按下述步骤进行网页验收，实际点击前不替用户支付任何订单。

## 网页测试步骤

1. 刷新网页，重新创建一笔有库存的演示商品订单。旧超时订单不能复用。
2. 支付页应出现“模拟付款（不扣款）”。点击后应显示“模拟付款成功（未扣款）”；我的订单显示已付款待发货。
3. AI发送“我的订单”，复制本轮新订单项ID，不要用支付单号或旧截图号。
4. 发送“可以申请退款吗 真实订单项ID”，应可提交审核。若已被原自动物流流程推进为已发货，则按真实状态测试“退货退款”，不硬改订单状态。
5. 发送“申请退款 真实订单项ID，原因：商品质量问题”，出现确认卡。先取消一次，再重新发起并确认。
6. 确认后应为PENDING_REVIEW，并说明尚未执行退款；重复申请拒绝。模拟付款完成不等于售后申请获批。

未来重启从项目根目录运行stop-local.cmd、start-local.cmd -WebOnly；源码变更用-Rebuild。旧占位说明仍是历史记录，以本节新能力为准。正式环境不能开启这两个模拟开关，也不能用本功能替代支付宝签名验证。

## 面试讲法

“为了在本地验证售后成功链路，我补了受控的模拟付款入口。身份和金额都来自Java，先拿原支付生命周期锁，拒绝超时和真实交易，然后复用原支付成功处理。因此演示不需要真实资金，也没有用SQL直接伪造状态。模拟记录有独立流水前缀；默认关闭，生产环境冲突时拒绝启动。”

追问‘前端隐藏够不够’：不够，后端还要开关、登录归属、状态、超时、幂等和真实交易标记检查。追问‘重试怎样’：同模拟流水返回原成功，未确认结果先读服务器，不在浏览器自行设paid；跨服务失败仍受原支付流程的恢复能力约束，不承诺绝对exactly-once。
