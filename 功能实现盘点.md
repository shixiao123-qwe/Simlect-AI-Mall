# Simlect 商城功能实现盘点

检查日期为 2026-11-04。本文依据当前工作区源代码进行静态检查，覆盖用户端、管理端、Java 业务服务及 Python Agent。默认采用 Markdown，便于随项目维护。

“已有实现”表示找到页面或接口以及相关处理代码。“存在入口”表示仅能确认入口或文件存在。本文未执行本轮构建、自动化测试及支付、物流、模型服务联调，因此所有条目均保留运行验收状态，不据此计算完成百分比。

## 1. 总体情况

项目已形成商品浏览、购物车、下单、支付处理、发货物流、确认收货、评价及售后申请的业务代码体系，同时包含会员签到、优惠券、消息通知、后台运营和 AI 导购。用户端提供 PC 与移动适配页面，管理端也包含移动页面。核心交易和 AI 功能仍需结合外部服务配置进行端到端验收。

## 4. AI 助手与智能导购

- 对话入口已有历史消息、发送、取消生成、商品咨询上下文设置及清理、WebSocket 通道。证据为用户端 agentApi、AgentChatList.vue、AgentSendPanel.vue，以及 Agent 的 app/api/routes/agent.py、app/api/websocket.py。
- 工具执行通过 MCP 服务提供商品搜索、商品详情、订单列表、订单详情、物流、已提交评价、用户优惠券等查询。真实注册入口为 app/mcp_server/server.py。
- 导购支持结构化品类、价格范围、硬属性、软偏好筛选。shopping_service.py 并行召回关键词与向量候选，RRF 合并后调用 Java /internal/product/ai/filter 核验 SKU、库存和硬约束，再生成商品卡片。
- 商品对比支持 2 至 3 款不同商品，使用已核验价格、库存及已录入参数生成结论，缺失参数有显式提示。
- 确认收货、退款、评价和追评具有提案工具，相关执行逻辑位于 pending_action_service.py 与 action_execute_service.py。用户端存在 confirmAction、cancelAction 接口调用。
- 售后工具包含政策查询、订单项资格检查、申请确认卡、本人申请进度。CREATE_AFTER_SALE_REQUEST 注册说明明确要求用户确认后才提交 Java 待审核申请。
- 已存在会话记忆、上下文构建、压缩、意图识别、输入输出及工具护栏模块。相关目录为 app/memory、app/domain/intent、app/harness/guardrails。

运行约束包括模型、Embedding、Elasticsearch、Redis 和 MCP 服务可达。严格导购代码要求 INTERNAL_READ_BACKEND=http，其他模式会返回不可用提示。

## 5. 交易与售后的实现边界

### 5.1 订单

OrderInfoServiceImpl.postOrder 包含地址归属、商品上下架、SKU、数量、库存、优惠券等业务校验，随后组织跨服务操作。代码采用 Seata 全局事务，并包含 Outbox 和延迟关单处理，订单状态通过状态机流转。删除采用业务限制与逻辑删除。相关并发和补偿代码需要通过中间件集成测试验证实际效果。

### 5.2 支付

PayChannel4AliPay 已实现支付链接、支付通知解析、主动查单、退款和关单方法。项目同时有受配置控制的本地模拟支付路径，LocalDemoPaymentService 会检查本人订单、状态和超时，再进入支付成功处理。

验收时应记录当前启用真实渠道、沙箱还是本地模拟。本轮未验证渠道密钥、回调可达性和真实资金结果。

### 5.3 售后

AfterSaleWorkflowService 已包含管理员审核、退货物流提交、验收、退款执行、退款失败状态及原退款单号重试保护。退货退款会进入 WAIT_RETURN、WAIT_INSPECTION、READY_REFUND 等阶段。退款调用会复查订单项结果，再记录金额及退款标识。

售后退款执行受 simlect.after-sale.refund-enabled 控制，代码默认 false。模拟执行状态也有单独标记。退款履约代码明确支持 refund 与 return_refund，其他类型会报“此类型尚未支持退款履约”。这些条目应标记为已有流程实现、启用及渠道结果待验证。

## 6. 工程支持与验证状态

已有 Maven 多模块、Docker Compose 中间件配置、前端构建与部署脚本、PWA 配置。测试源码涉及 Java 订单状态机和售后流程，以及 Python Agent 图、鉴权、商品相关性、记忆、确认动作和 WebSocket。仓库另有 evals 导购和售后评测脚本。

本轮采用源代码静态阅读和入口交叉检查，未运行测试。已有 target 测试产物的存在不能证明当前代码通过。本轮也未进行数据库迁移、真实下单支付、邮件发送、物流渠道、模型和 RAG 联调。

建议验收记录以单个场景为单位记录环境、输入、预期、实际与证据，优先覆盖注册登录、SKU 下单与库存不足、重复支付通知、超时关单、优惠券回退、退货退款与重试、AI 写操作确认和跨用户数据访问。
